## 1. 模型调用约束（ModelGateway）
- 新增 `core/model-gateway.ts` 接口：`complete()` / `json(schema)` / `discover()`；现有 OpenAI 兼容实现成为唯一实现 `OpenAICompatibleGateway`（原生 fetch，不引入任何厂商 SDK）。
- 积木只能通过 `ctx.llm`（内部持有 ModelGateway）调用模型；积木代码禁止导入 gateway 实现、fetch 模型地址。
- `llm_providers` 增加 `provider_type text not null default 'openai_compatible'`，CHECK 仅允许 `openai_compatible`；base_url、模型 ID、API Key 全部来自 `llm_providers` / `model_routes` / `secrets`。
- 积木声明 `taskTier`（fast/standard/deep），不写模型名。
- 密级：应用 `classification` 为 `sensitive` / `confidential` 时，仅允许 `allowed_for_sensitive = true` 的服务；默认值为 false，因此默认禁止；拒绝时步骤进入 `failed`，错误码 `LLM_SENSITIVE_FORBIDDEN`，不降级、不编造。
- 未配置路由时步骤显示「需要配置模型」（`LLM_NOT_CONFIGURED`），状态 `waiting_model`，不生成内容。
- 自动化守卫测试：扫描 `src/`（不含测试与文档），不得出现 `deepseek`、`api.deepseek.com`、固定模型名或厂商 SDK 依赖。

## 3. 工作流状态机

```text
pending -> running -> succeeded
任一非终态 -> cancelled (取消运行)
                   -> waiting_human -> succeeded (approve)
                                    -> rejected  (reject，回到 goto 目标)
                   -> waiting_model -> running (重试) / failed (12 次后)
                   -> failed -> running (手动重试，attempt+1)
pending -> skipped (when 不成立 / 档位跳过 / optional 停用 / lead 手动跳过+原因)
任一非终态 -> superseded (被退回或重跑覆盖)
run: running | waiting_human | waiting_model | failed | completed | cancelled
```
- 运行状态由当前步骤推导，同一事务内更新，并用 `lock_version` 做乐观锁。
- **原子领取**：`claim_step` 锁定运行行，取当前序号最小的 pending 步骤，写入 `lease_token` 并设置 60 秒租约后返回；租约过期才可重新领取。一个运行同一时间最多只有一个 running 步骤（部分唯一索引）。
- **attempt 历史**：重试、退回、重跑都会新增一行 `step_runs`（attempt+1），旧行改为 `is_current=false`，保留事件、摘要和产出。
- **退回**：goto 只能指向当前或之前的步骤（启动时与决策时都校验）；从 goto 到当前步骤之间每一步新建 pending attempt，旧 attempt 标记 superseded；这些旧 attempt 产生的草稿制品标为 superseded、发现和问题标为 stale；退回意见写入新 attempt 的 `checkpoint.feedback`，交给积木使用。
- **下游失效**：只有运行中的退回或明确的「从某步重跑」才会让下游自动重新排队；运行结束后人工修改制品/需求，只在下游步骤和相关制品上提示「可能已过期」，不自动重跑。已批准版本保持不变，需求版本只增不删。
- **超时**：running 步骤超过 5 分钟没有心跳则标为 failed（`STEP_STALLED`），并显示「重试」；waiting_model 按 `wait_reason` 区分：`model_not_configured` 不自动重试，配置好后由用户点「重试」；`model_unavailable` / `rate_limited` 每 5 分钟重试一次，最多 12 次；waiting_human 不自动超时（提醒功能放到后续批次）。
- **格式错误**：`ctx.llm.json` 用 Zod 校验，格式不符时附带错误说明自动重试 1 次；仍失败时步骤 failed（`LLM_BAD_FORMAT`），原始响应只给 admin/lead 查看，并已脱敏。
- **权限**：启动运行：lead/ba/admin；确认：checkpoint 指定角色（B03 为 ba），或者 lead/admin；跳过：仅 lead，必须填写原因，写入审计；取消/重跑：lead 或发起人；全部写操作记入 `audit_logs` 和 `step_events`。

## 4. Cloudflare Workers 上的长任务
- Workers 不适合长时间后台执行，因此采用**分片执行**：每次调用最多处理约 20 秒，积木返回 `{continue:true, cursor}`；引擎在一个事务内保存 cursor、进度和本批结果（按 `(step_run_id, attempt, cursor_seq)` 幂等写入），然后释放租约。
- **推进来源**（都要经过 `claim_step`，不会重复执行；页面只查看状态，`useLiveRun` 不调用 tick）：
  1. 启动/确认/重试接口立即同步执行一个分片，并通过 `waitUntil` 再续一片；
  2. 定时调度每分钟执行 `sdf_engine_sweep`：数据库内处理超时和重试到期，再调用签名接口 `/api/public/hooks/engine-tick`（大小 → 时间戳 → 签名 → nonce → 执行）。
  - 需要配置 `SDF_CRON_SECRET`（2A 开始前通过安全表单添加，密钥放 Vault，不写入迁移或普通表）。
- **分片幂等**：每个分片结果写入 `step_chunk_results`（主键 step_run_id+attempt+cursor_seq），重复执行不会产生重复数据；最后一个分片完成后由 `merge_step_results` 在一个事务中合并并推进状态。
- **断点恢复**：租约过期后由下一次 tick 从已保存的 cursor 继续。
- trace：后台分片沿用运行的 `trace_id`，日志带 `run_id` 和 `step_run_id`。

## 5. 积木规格（`src/core/blocks/*`，manifest + run，工作流和单独执行共用同一套代码）

| 积木 | 输入 | 输出 | 校验 | 事务/分批 | 权限 |
|---|---|---|---|---|---|
| B01 资料导入（分阶段：①上传到存储 ②建 source 记录 parse_status=uploaded ③服务端解析文本（不在数据库事务内） ④一个事务写入全部段落 ⑤智能体分片标注） | 上传文件（≤10MB，txt/md/docx/pdf）或粘贴文本（≤200k 字）、kind、标题、会议日期、参与人 | `sources`、`source_segments`、`source_segments` 制品；智能体标注发言人/议题/结论/待办 | MIME 与扩展名一致；解析为空则报错；段落 ≤ 2000 段 | 解析失败只把 parse_status 设为 failed 并保留文件；段落一次性事务写入；标注每批 15 段写入 step_chunk_results | lead/ba 上传；成员查看 |

| B04 澄清问题 | 最新需求和发现、联系人 | `clarification_questions`（按提问对象分组）+ 制品 | 每个问题至少关联 1 条需求或发现；回答 ≤ 5000 字 | 生成问题一次性写入；「根据回答更新需求」作为单独操作，调用 B02 update 逻辑生成新版本 | lead/ba 录入回答 |

## 7. 页面功能
- **运行详情** `/apps/:appId/runs/:runId`：头部（编号、工作流、档位、当前状态与等待时长、发起人、取消/从选中步骤重跑）；按阶段分组的顶部步骤条（确认点用菱形，当前步骤唯一闪烁，悬停显示摘要）；左侧步骤列表（状态、用时、「确认·角色」、「第 N 次」可展开历史）；右侧 5 个标签页：概况（正在做、结果摘要、错误编号、重试、导出诊断包）、执行记录（实时追加）、输入和结果（制品预览和差异）、智能体（角色、提示词版本、模型、Token；原始请求仅 admin/lead 可展开）、确认（提示、意见、通过/退回到某步）。
- **运行列表**：应用「运行」标签页，可按状态筛选；应用卡片和概览显示缩略步骤条。
- **工作流** `/workflows`：列表、YAML 查看、校验结果、计划预览（使用同一步骤条，跳过步骤显示虚线）、启动运行（选择应用、档位、输入）；本批没有「复制为自定义」按钮。
- **我的待办** `/inbox`：我有权确认的 waiting_human 步骤，显示缩略步骤条和等待时长，可直接跳转到确认页；其它待办类型显示「尚未实施」。
- **需求标签页**：原始资料（上传、段落和发言人、原文）、需求和验收标准（出处可点击查看原文、版本差异、置信度）、分析问题（按级别筛选、状态处理）、澄清问题（按对象分组、录入回答、据此更新需求）；另有工程规范表单。
- 实时刷新沿用 `useLiveRun`（只读）；订阅失败时每 5 秒查询，并显示「已改为定时刷新」。
- 运行结束后修改过的制品，在下游步骤和制品上显示「可能已过期」标记。
